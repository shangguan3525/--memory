# 公文通用规范

> 这是**结构规范**，不是任何单位的正式范文。示例段落均为虚构，只演示骨架。

## 一、要素顺序

```
标题（发文机关 + 事由 + 文种）
主送机关：
正文 —— 缘由（为什么现在写）→ 事项（分条，一条一个动作）→ 结语
附件：1. ××  2. ××
发文机关署名
2026年10月20日
```

## 二、五条硬规矩

1. **一文一事**：请示、报告不要在正文后夹带第二个请求。
2. **报告不夹请示**：报告只汇报；要批的事另发请示。
3. **成文日期用阿拉伯数字**：2026年10月20日，不写"二〇二六年"。
4. **层次序数固定**：一、 → （一） → 1. → （1）；不要用"1、"，不要跳级。
5. **每条事项可执行**：有人、有量、有时限；写不出这三样的条目，删掉。

## 三、高频用语

| 场景 | 用语 |
| --- | --- |
| 引出事项 | 现将……印发给你们 / 现就……通知如下 |
| 引用依据 | 依据《××》（文号）/ 经研究 |
| 请示结语 | 妥否，请批示。 / 请予审批。 |
| 报告结语 | 特此报告。 |
| 通知结语 | 特此通知。 |
| 函的结语 | 请予支持为盼。 / 盼复。 / 特此函复。 |

## 四、五条禁忌

口语化表达、"我们认为/我觉得"、无责任人的部署、无测算的金额、无时限的整改。

## 五、自查清单（发出去之前逐条打勾）

- [ ] 标题三要素齐全，文种没写错（请示≠报告）
- [ ] 主送机关只有一个层级，没有既报上级又抄平级当主送
- [ ] 每个"事项"都有责任主体和时间
- [ ] 金额/数据有测算依据或出处
- [ ] 附件在正文里有对应说明（"详见附件 1"）
- [ ] 结语与文种匹配
